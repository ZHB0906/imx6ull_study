# 第 44 章　烧卡与验证说明

**镜像**：`sdcard-ch44.img`（本次新增：新设备树 + 驱动模块 + 测试程序）
**基线**：`sdcard.img`（sha256 `209e8ed50edafc65...`，就是你 9/13 烧卡用的那份）
**生成方式**：保留 u-boot / 环境区 / p2 rootfs 原封不动，**只重建了 p1（FAT32）分区**

---

## 一、这一版和上一版的区别

| 内容 | 上一版（sdcard-my-led.img） | 本版（sdcard-ch44.img） |
|---|---|---|
| 设备树 `7-1024x600` | 40381 字节，`my-led` | **40574 字节，`my-led` + `alphaled` 节点** |
| `dtsled.ko` | 无 | **8440 字节（新增）** |
| `ledtest` | 无 | **7980 字节（新增）** |
| 其余 6 个屏的 dtb | 40381/41217/41125 | 同左，**未动** |
| zImage | 7103248 | 同左，**未动** |
| u-boot / 环境区 / rootfs | — | **逐字节未动** |

**为什么要重建 p1 而不是打补丁**：原镜像的 FAT32 根目录跨了 2 个簇（簇 2 + 簇 14114），
"原地打补丁"时读写地址反复对不上。最后改成用自己写的 `fat32build.py`
重新生成整个 64MiB 分区，几何完全可控，并用 `fsck.vfat` 验证通过（零错误零警告）。

## 四、上电（⚙️ 拨码已在 SD 卡档，不用改）

之前已经设好，直接上电即可。u-boot 环境里已经有：

```
mmcdev=0                          # SD 卡槽
mmcroot=/dev/mmcblk0p2            # SD 卡的 rootfs 分区
fdt_file=imx6ull-14x14-emmc-7-1024x600-c.dtb
```

⚠️ **烧卡会覆盖 u-boot 环境区吗？** 不会 —— 环境区在偏移 786432，
而镜像里那块是原样保留的。但**如果你烧完发现环境丢了**（开机又是
`*** Warning - bad CRC`），说明 u-boot 用回了编译默认值（`mmcdev=1` = eMMC），
这时按第六章"兜底"操作。

## 五、验证第 44 章（🐧 板子 Linux）

### ① 确认启动自 SD 卡

```bash
ls /sys/class/leds/
# 应该【没有】my-led 了！因为 gpio-leds 被我们 disable 了
# 预期输出：beep  mmc0::  mmc1::
```

> ⚠️ **这一步很关键**：如果还能看到 `my-led`，说明板子用的还是旧 dtb，
> 新 dtb 没生效，后面的实验做不了。

### ② 把驱动和测试程序拷出来

它们就在 SD 卡的 p1 分区（FAT32）里。板子上挂载它：

```bash
mkdir -p /mnt/sd1
mount -t vfat /dev/mmcblk0p1 /mnt/sd1
ls /mnt/sd1
# 应该看到：dtsled.ko  ledtest  zImage  imx6ull-*.dtb ...
```

拷到 rootfs 里（因为 FAT32 不支持 Linux 的权限位，模块要从 ext4 加载）：

```bash
cp /mnt/sd1/dtsled.ko /root/
cp /mnt/sd1/ledtest   /root/
chmod +x /root/ledtest
cd /root
```

### ③ 加载驱动

```bash
insmod dtsled.ko
dmesg | tail -20
```

**期望输出**：

```
alphaled node find!
compatible = atkalpha-led
status = okay
led_gpio num = 3
dtsled major=24x, minor=0
```

> ### ⚠️ 重要修正（已修复）
>
> 第一版驱动上板报了这个错：
>
> ```
> dtsled: Unknown symbol _GLOBAL_OFFSET_TABLE_ (err 0)
> insmod: can't insert 'dtsled.ko': unknown symbol in module or invalid parameter
> ```
>
> **原因**：Ubuntu 的 `arm-linux-gnueabihf-gcc` 是**默认 PIE** 编译的
> （`gcc -v` 里能看到 `--enable-default-pie`）。这版内核（4.1.15）的
> `arch/arm/Makefile` **没有显式加 `-fno-pic`**，编内核主体时不成问题，
> 但编**模块**时 PIC 就漏进来了，`.ko` 里出现
> `R_ARM_BASE_PREL` / `R_ARM_GOT_BREL` 两种 PIC 重定位，
> 并多出一个未定义符号 `_GLOBAL_OFFSET_TABLE_`，`insmod` 直接拒绝。
>
> **修法**：Makefile 里加
>
> ```makefile
> ccflags-y += -fno-pic -fno-PIE
> CFLAGS_dtsled.o += -fno-pic -fno-PIE
> ```
>
> 修好后 `.ko` 从 8440 → **8360 字节**，PIC 重定位和该符号都消失。
> （2026-09-14 又升级为 platform driver 版 → **11076 字节**，大小变了但 PIC 检查照旧，
> 原因与验证见 `第44章_设备树下的LED驱动.md` 第九节。）
> **本版镜像里装的是修复版。**
>
> **自己确认命令**（在虚拟机上）：
>
> ```bash
> arm-linux-gnueabihf-readelf -rW dtsled.ko | grep -E 'GOT|BASE_PREL'
> # 没输出 = 修复成功
> arm-linux-gnueabihf-readelf -sW dtsled.ko | grep _GLOBAL_OFFSET_TABLE_
> # 没输出 = 修复成功
> ```

**判据**：

```bash
ls -l /dev/dtsled          # 设备节点存在
```

### ④ 控制 LED

```bash
./ledtest /dev/dtsled 1    # 点亮（板子上的红灯）
./ledtest /dev/dtsled 0    # 熄灭
```

> **低电平有效**：`1` 在驱动里被翻译成 `gpio_set_value(gpio, 0)`。
> 如果亮灭反了，说明这里理解反了 —— 看 `dtsled.c` 的 `led_switch()`。

### ⑤ 卸载

```bash
rmmod dtsled
ls /dev/dtsled             # 应该不存在了
dmesg | tail -5
```

### ⑥ 验证设备树属性读取（第 43 章知识点）

```bash
cat /proc/device-tree/alphaled/compatible ; echo    # atkalpha-led
cat /proc/device-tree/alphaled/status ; echo        # okay
```

## 六、兜底：如果 u-boot 环境丢了

🔧 在 `=>` 提示符下（上电时连按回车打断）：

```text
setenv mmcdev 0
setenv mmcroot /dev/mmcblk0p2 rootwait rw
setenv fdt_file imx6ull-14x14-emmc-7-1024x600-c.dtb
saveenv
boot
```

## 七、排错

| 现象 | 原因 | 解决 |
|---|---|---|
| **`Unknown symbol _GLOBAL_OFFSET_TABLE_`** | **模块被编成了 PIC**（Ubuntu gcc 默认 PIE） | Makefile 加 `-fno-pic -fno-PIE`，见第五章③的修正说明 |
| `ls /sys/class/leds/` 还有 `my-led` | 板子用的还是旧 dtb | 确认烧卡成功；检查 `/mnt/sd1` 里 dtb 大小是否为 40574 |
| `alphaled node not find!` | 设备树没生效 | 同上 |
| `insmod: can't insert 'dtsled.ko': Invalid module format` | vermagic 不匹配 | 必须用同一份内核源码树编 |
| `gpio_request failed` | gpio-leds 没关掉，GPIO 被占 | 确认设备树里 `/leds` 是 `status = "disabled"` |
| `get led-gpio failed!` | 属性名写错 | 设备树和代码里都必须是 `led-gpio` |
| `insmod: not found` | 模块不在 ext4 上 | 必须先 `cp` 到 `/root`，不能直接从 FAT32 加载 |
| LED 不亮但没报错 | 低电平有效写反 | 交换 `gpio_set_value` 的 0/1 |
| `mount: /dev/mmcblk0p1: unknown filesystem` | 内核没编 vfat | 检查 `CONFIG_VFAT_FS=y` |
